# Configuration reference

Caboodle writes a reviewable TOML plan and a JSON progress file. Use the CLI to
create the plan; keep credentials in the environment, never in intent text.
The plan's schema rejects unknown keys.

## Plan: `caboodle-plan.toml`

| Key | Meaning |
|---|---|
| `schema_version` | Plan schema version, currently `1`. |
| `profile` | `kg`, `retrieval`, `code-intel`, `everything` or `crew`. |
| `tools` | Ordered tool selection derived from the profile. |
| `shares` | Canonical Quipu share directories to stage during apply. |
| `quipu_db` | Explicit destination database, required when shares are selected. |
| `quipu_flavor` | `release` (default) or `lancedb`; see [profiles](profiles.md#quipu-install-flavor). |
| `stack_config.quipu.owl.reactive_materialize` | Recommended OWL materialization setting merged into Bobbin's config. |
| `crew.mode` | `shantytown`, `creel`, `both` or `standalone`. |
| `crew.durable_owner` | Shantytown for durable crew work, when selected. |
| `crew.burst_owner` | Creel for browser bursts, when selected. |
| `crew.routing` | `single-owner` or `explicit-handoff`, derived from the mode. |
| `crew.policy.identity_source` | `quipu`; crew identity authority. |
| `crew.policy.model` | Optional model selection. |
| `crew.policy.tools` | The crew profile's tool set. |
| `intent` | Intended-use contract described below. |
| `embedding_model.destination` | Directory for the model artifacts. |
| `embedding_model.artifacts` | Array of entries, each with `name`, HTTPS `url` and `sha256`. |

Crew ownership fields must match the selected mode. Do not hand-edit them into
an alternative routing scheme. [Profiles](profiles.md) explains the contracts.

## Intent: `caboodle-intent.toml`

| Key | Meaning |
|---|---|
| `intended_use` | Nonempty plain-language purpose. |
| `crew_members` | Array with `name`, `theme`, `domain`, `role`; may be empty. |
| `anticipated_questions` | At least one executable reader-path question. |
| `anticipated_questions[].question` | The question in words. |
| `anticipated_questions[].answer_shape` | Shape of the expected answer. |
| `anticipated_questions[].seed_intent` | Facts required before the query can pass. |
| `anticipated_questions[].sparql` | `SELECT` or `ASK` query. |
| `anticipated_questions[].expected` | Marker required in its result. |
| `anticipated_questions[].self_test` | Built-in scratch-store check flag; normally generated by the interview. |

`plan` embeds the intent in the plan. `verify-questions` executes those queries;
custom questions require their seed facts in the target database first. The
built-in interview self-test instead seeds its own temporary store. Installing
and verifying tools does not seed a user's production graph.

## Local state and targets

`.caboodle/state.json` is generated progress, not user configuration. It records
tools, model artifacts and staged shares. Preserve it to resume an interrupted
apply or update. `.caboodle/interview.toml` checkpoints interview answers;
`.caboodle/episodes/` retains queued install records until confirmed delivery.

`caboodle-observability.toml` contains a `[targets]` table with `quipu` and, when
selected, `bobbin` keys. Values are Prometheus `host:port` destinations, without
a URL scheme or path. Rendering produces files for review, not a live scrape.
See [emission](emission.md) and [proofs](proofs.md) for those boundaries.

## Environment

| Variable | Purpose |
|---|---|
| `HOME` | User configuration, data and default install directories. |
| `CARGO_HOME` | Overrides the binary destination root; binaries go in its `bin/`. |
| `PATH` | Must find the installed binaries before stale copies. |
| `CABOODLE_CAMAYOC_ROOT` | Override the Camayoc distribution root. |
| `QUIPU_SERVER` | Existing Quipu server for operations that need one; temporary functional checks remain isolated. |
| `QUIPU_AUTH_TOKEN` | Environment-only bearer used by episode delivery. |
| `CABOODLE_HOLD_FILE` | Override the release-update hold marker, default `~/.caboodle/hold`. |
| `SHANTY_TOOLING_MANIFEST` | Shantytown's managed rig registration manifest; see [agent setup](installing.md#registering-mcp-servers). |

The shell release installer also accepts `CABOODLE_VERSION`,
`CABOODLE_INSTALL_DIR`, `CABOODLE_TARGET`, `CABOODLE_REPOSITORY` and
`CABOODLE_RELEASE_BASE_URL`. The last two select the download authority; keep
them unset for official releases. These are installer inputs, not plan keys.
